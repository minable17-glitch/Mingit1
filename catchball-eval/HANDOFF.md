# 캐치볼 영상 평가 — 인수인계 문서

이 문서는 다른 AI 코딩 세션에 그대로 붙여넣어 이어서 작업하는 용도입니다. 사용자는 비개발자 교사이므로 항상 쉬운 말로 설명해야 합니다.
새싹책방(Mingit1 저장소)에서 분리해 나온 프로젝트이며, **수파베이스 프로젝트도 전용**으로 씁니다. 사용자의 명확한 요구: 새싹책방과 절대 겹치지 않게(코드, 저장소, DB, 계정 모두 분리).

## 1. 전체 구조

체육 수행평가용. 두 학생이 캐치볼하는 영상을 올리면 **노란 공**과 아이들의 **손목·발목**을 인식해 성공(잡음)/실패(떨어뜨림) 횟수를 자동으로 세고, 선생님이 고쳐서 저장하는 도구. 영상 인식은 전부 브라우저에서, 영상·기록 저장은 수파베이스에서. 원래 새싹책방(Mingit1) 저장소 안의 별도 페이지로 만들었다가 이 저장소로 분리함.

**주소**: 배포 시 `https://<아이디>.github.io/<저장소>/` 하나 (학생·선생님 공통, 위쪽 버튼으로 전환, `?teacher` 로 선생님 화면 바로 열기). 개발 시 `http://localhost:5173/`. 배포는 `.github/workflows/deploy.yml` (main 에 push → GitHub Pages. 저장소 Settings > Pages > Source 를 GitHub Actions 로 두어야 함).

**동작 방식 (영상은 절대 서버로 올라가지 않음, 전부 브라우저 안에서 처리)**
1. 영상 파일 선택 즉시 자동으로 채점 시작 (`src/App.jsx` → `startAnalysis`).
2. `analyzer.js`: 영상을 초당 15장(설정 가능)으로 `currentTime` 을 옮겨가며 한 장씩 읽음. 분석용 너비 640px 로 축소.
3. 공: `analysis.js`. 실제 영상(2026-11, 운동장·단풍·손떨림·글러브)으로 맞춘 **궤적(tracklet) 방식**.
   - `detectBallCandidates`: HSV 색(기본 주황~노랑: 색상 15~65, 채도 ≥30%, 밝기 ≥40%)으로 마스크 → 연결 덩어리 → 크기(4px~화면의 0.4%)·모양·속 픽셀(8px 이상일 때만)·고정물 지도(`createStaticMap`, 3초 이상 같은 칸) 통과한 **후보 전부**(최대 40개).
   - `createTrackletTracker`: 후보들을 프레임 간에 이어 붙여 궤적을 만들고, **"던진 공"으로 확정되는 조건**을 모두 만족한 궤적만 공으로 인정: 1.6초 창 안에서 가로 이동 ≥ 화면의 8%, 한 방향으로 매끄러움(경로 길이 ≤ 순이동의 1.1배), 프레임당 이동이 고름(최대 ≤ 중앙값의 2.5배), 속도 ≥ 0.015/프레임, **중력 검사**(세로 좌표 2차 맞춤의 가속도 ≥ 0.0012/프레임², `quadraticAccel`), 영상 첫 1초 제외. 확정되면 `onConfirm` 으로 앞 프레임들을 채움. 확정 후 0.4초 넘게 느려지면(잡힘) 궤적 종료 → 글러브·손을 계속 따라가지 않음.
   - `createCameraMotion`: 1/8 축소 흑백 블록 매칭(거친 ±10블록 → 세밀 ±2)으로 카메라가 밀린 양을 재고, 확정 판단은 이를 뺀 좌표(`cx, cy`)로 함. 손떨림·팬 중에 고정물(낙엽·울타리·나무)이 '날아간' 것으로 보이는 것을 막음.
   - 분석 해상도 960px (`ANALYSIS_WIDTH`, `LIVE_WIDTH`). 640에서는 멀리 있는 공이 4픽셀이라 못 잡음.
   - 실제 영상 v2(두 아이, 23초)에서 실제 비행 5회를 모두 잡고(8–9.5s, 11.4–12.3s, 14.1–15.9s, 17.3–19s, 21–22.6s), 공을 떨어뜨리고 줍는 5–7초 구간과 카메라 팬에서 거짓 이벤트 2~3개가 남음. 떨어뜨림 판정은 바닥선이 필요해 포즈(발목)가 잡히는 브라우저에서만 됨(오프라인 도구는 기본 0.88이라 못 잡음).
   - 디버깅: `CONFIRM_LOG=1 TRACK_OUT=t.json node scripts/catchball-offline.mjs 영상` → 확정 통계와 궤적 저장. 세션 scratchpad 의 `plot.py`/`annot.py` 로 x(t)·y(t) 그림과 검출 위치 오버레이 타일을 만들어 확인했음(저장소엔 없음).
4. 사람: `pose.js` — MediaPipe PoseLandmarker(lite, numPoses 2). wasm 은 npm 패키지에서 같이 번들되고(`?url` import, exports 에 없어서 `node_modules` 경로로 직접 가져옴), 모델 `.task` 파일(약 5MB)만 `storage.googleapis.com` 에서 받음. 못 받으면 손 없이 공 궤적만으로 판정하고 화면에 안내.
5. 판정: `analysis.js`의 `detectEvents` — 공 x 좌표의 **지그재그(방향 전환) 감지**. 화면 너비의 12%(설정 `최소 던지기 거리`) 이상 날아갔다 되돌아온 지점이 '잡힌 순간'. 그 전환점 전후(날아온 거리 70% 지점 ~ 되돌아간 거리 30% 지점)에 공이 바닥선(발목 기준, 없으면 y 0.88) 아래로 갔거나 튀어오른 흔적이 있으면 **실패**, 아니면 **성공**. 손목이 공 근처(화면 10%)에 있었으면 확신도 95%.
6. 결과 화면: 성공/실패/최대 연속/성공률 + 이벤트 목록(시각 누르면 그 장면으로 이동, 성공↔실패 토글, 삭제, 현재 장면에 추가). 영상 재생 중 공 궤적·손목·바닥선이 오버레이로 그려짐.
7. 저장: `records.js` — `localStorage`(`catchball_records_v1`)에 저장, 엑셀(`xlsx`)로 내려받기 (시트 2개: 평가기록, 캐치시점).

**검증 상태**: 실제 촬영 영상 없이 만들었음. 합성 영상(캔버스로 그린 두 사람 + 노란 공 + 고정된 노란 콘, 성공 9회·실패 1회)으로 브라우저 종단 테스트를 통과함(정확히 9/1). **사용자가 실제 영상 샘플을 주면 `scripts/catchball-offline.mjs` 로 먼저 돌려보고 색 기준값·판정 기준을 맞출 것.**

```
node scripts/catchball-offline.mjs 영상.mp4            # ffmpeg 필요. 포즈 인식 없이 공 궤적만으로 판정
DUMP=8-12 node scripts/catchball-offline.mjs 영상.mp4  # 8~12초 구간 프레임별 공 위치 출력
```
브라우저에서는 채점이 끝난 뒤 콘솔에서 `window.__catchballDebug` (track, events, groundY)로 같은 데이터를 볼 수 있음.

### 12-1. 학생 제출 화면 + 수파베이스 저장 (`src/upload/`, `supabase/catchball.sql`)

학생이 로그인 없이 영상을 올리고, 선생님이 이 도구 전용 계정(`catchball_teachers`)으로 로그인해 채점·기록하는 구조. **전용 수파베이스 프로젝트** 사용 (설정 순서는 README).

- **DB/스토리지 설정** (`supabase/catchball.sql`): 전용 프로젝트의 SQL Editor 에서 실행 (익명 로그인을 먼저 켜야 함). 내용: 버킷 `catchball-videos`(비공개, 50MB 제한, video/* 만), 테이블 `catchball_teachers`(아이디+bcrypt 해시), `catchball_teacher_sessions`(익명 세션 ↔ 선생님 매핑), `catchball_settings`(가입 코드 `signup_code`, 기본 `catch-2026`), `catchball_submissions`(제출), `catchball_results`(채점), RPC `catchball_teacher_signup/login/me/logout/change_password/submit/list_submissions/save_result/list_results/delete_result/delete_submission`, storage 정책(올리기: 자기 uid 폴더만 / 읽기·삭제: 선생님만). 첫 선생님은 코드 없이 가입, 그 뒤는 가입 코드 필요.
- MCP 로 새 수파베이스 프로젝트를 만들려 했으나 자동 승인에서 거부됨 → 사용자가 대시보드에서 직접 만들고 URL/키를 `deploy.yml` 에 넣는 방식.
- **학생 페이지** (`src/upload/`): 두 가지 모드.
  - 📹 **바로 촬영해서 제출** (`LiveCapture.jsx` + `live.js`): 촬영하는 동안 같은 인식 코드로 공·손목(글러브)·발목(바닥선)을 실시간으로 잡아 성공/실패를 화면에 셈(0.5초마다 `detectEvents` 재계산). 촬영 끝과 동시에 녹화 파일(MediaRecorder, 1.5Mbps)과 자동 카운트를 **자동 업로드**. 느린 기기에서는 포즈 인식 간격을 자동으로 늘림(한 번 걸린 시간의 3배 휴식).
  - 📁 **찍어 둔 영상 올리기**: 브라우저에서 640px 로 다시 녹화해 압축(`compress.js`, 1분 100MB → 5~10MB, 영상 길이만큼 걸림) 후 업로드. 50MB 넘으면 거부.
  - 업로드(`api.js`): 익명 로그인 → storage 에 XHR POST(진행률) 경로 `<uid>/<시각>_<파일명>` → RPC `catchball_submit`.
  - 학생 링크: 주소 그대로 (설정 없음). 선생님도 같은 주소에서 위쪽 버튼으로 전환.
- **선생님 화면** (`App.jsx`): 맨 위 로그인/계정 만들기 칸(전용 계정) → "학생이 제출한 영상" 목록(자동 카운트 표시, ✕로 영상 삭제해 용량 정리) → 채점 버튼이 storage 에서 내려받아 자동 채점 → 저장 시 `catchball_save_result`(+제출 상태 '채점완료'). 로그인 안 해도 기기 저장(localStorage) 모드로 쓸 수 있음.
- **용량**: 수파베이스 무료 플랜 저장소 1GB. 압축/앱 촬영 영상(1분 5~10MB) 기준 100~200편. 채점 끝난 영상은 목록에서 지워 비우는 운영 전제. 더 필요하면 Pro 플랜.
- **검증 상태**: 수파베이스 호스트가 이 샌드박스 네트워크에서 막혀 있어(프록시 403) 실제 프로젝트로는 못 돌림. auth 익명 로그인·RPC·storage 를 흉내 낸 가짜 서버(scratchpad `mock-supabase.mjs`)로 학생 압축 업로드 → 선생님 로그인(틀린 비밀번호 거부) → 목록 → 내려받아 채점 → 저장 → 새로고침 후 세션 유지 → 영상 삭제 → 로그아웃, 그리고 가짜 카메라로 실시간 촬영 모드까지 브라우저 종단 테스트 통과. **실제 적용 후 첫 확인 포인트**: SQL 실행 후 버킷이 생겼는지, 학생 페이지 업로드가 403 없이 되는지(정책), 선생님 로그인 후 목록·다운로드가 되는지.

**알려진 한계 / 다음 할 일**
- 공이 화면에서 **좌우로** 오가는 영상(옆에서 촬영)만 판정 가능. 카메라 쪽으로 던지는 영상은 안 됨.
- 헤드리스 크로미움은 휴대폰 mp4(H.264)를 재생 못 하므로 자동 테스트는 webm 으로 변환해서 돌려야 함(실사용 브라우저는 문제없음).
- 한 화면에 여러 팀(공이 여러 개)인 영상은 판정 불가.
- 두 아이 이외의 사람·다른 팀이 화면에 있으면 손목 기준이 흐려짐 (포즈 2명까지만).
- 실패 판정은 바닥선에 의존. 포즈가 안 잡히면 기본 바닥선(0.88)이라 낮게 떨어진 공을 놓칠 수 있음 → 선생님 수정 전제.
- 선생님이 로그인하지 않으면 기록이 기기 localStorage 에만 저장됨.
- 영상 한 편 50MB 제한(버킷 설정). 앱 안 촬영·압축 업로드는 이 범위 안에 들어옴.
- 포즈 인식 wasm(11MB)은 npm 패키지에서 `?url` 로 번들됨 (`src/pose.js`). PWA/서비스워커는 쓰지 않음.
